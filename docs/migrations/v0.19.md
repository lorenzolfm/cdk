# Migration notes for v0.19

## LND backend initialization

The LND backend now calls `GetInfo` during `Lnd::new` to cache the node pubkey
and invoice network. Initialization requires a reachable LND node and a
macaroon that permits `info:read` or the specific `/lnrpc.Lightning/GetInfo`
RPC. This applies whether self-payments are enabled or disabled.

The standard `admin.macaroon` already permits this call. Before upgrading,
update custom restricted macaroons to permit `GetInfo` in addition to their
existing permissions. Missing permission or invalid node information now
returns an initialization error before the backend accepts payments.

The cached information lets the backend reject invoices for another network
and disallowed self-payments locally. Existing paid or pending payments are
reconciled before dispatch validation. These checks prevent new rejected
payments from getting stuck; they do not resolve previously pending quotes.

## SQLCipher is always enabled in cdk-sqlite

`cdk-sqlite` now always links SQLCipher, built against a vendored OpenSSL, and the
`sqlcipher` feature is removed from `cdk-sqlite`, `cdk-cli`, `cdk-mintd` and
`cdk-signatory`. A database opened with a password is encrypted with it; a
database opened without one is plaintext, as before.

- Remove `sqlcipher` from the `features` of these crates in your `Cargo.toml`
  and from `--features` in build scripts. Cargo rejects the unknown feature.
- Building OpenSSL from source needs `perl` and `make` on the build machine, and
  a clean build takes longer. No system OpenSSL is needed.
- `cdk-mintd`, `cdk-cli` and `cdk-signatory` no longer require `--password`.
  Builds that used the `sqlcipher` feature must still pass the same password to
  open their existing encrypted database. Without it, the open fails; it does
  not create a new database. Builds without the feature keep their plaintext
  database when no password is given.
- `cdk-mintd` now accepts `-p/--password` in every build with the `sqlite`
  feature, which is on by default.

## Wallet trait removal

The `cdk_common::wallet::Wallet` trait (often imported as `WalletTrait`) and
its implementations for the CDK and FFI wallets have been removed. Use the
inherent methods on `cdk::wallet::Wallet` or `cdk_ffi::wallet::Wallet` instead.
Remove trait imports and replace trait-qualified calls with inherent method
calls. Downstream generic bounds and custom implementations must migrate to
concrete wallet types or an application-owned trait.

The trait aliases `check_mint_quote`, `mint_unified`, and
`melt_human_readable` map to `check_mint_quote_status`, `mint`, and
`melt_human_readable_quote`, respectively. For FFI wallets, use the exported
method signatures and FFI types; for example, rate limiting is configured
through `set_rate_limit`. For native wallets, replace
`set_rate_limiting_config(None)` with `disable_rate_limiting()` and pass the
configuration directly to `set_rate_limiting_config` when enabling pacing.
The exported UniFFI API is unchanged.

## Payment request creation

`CreateRequestParams` adds optional `payment_id` and `nostr_pubkey` fields.
Rust callers using exhaustive struct literals must add these fields or use
`..Default::default()`. Set both to `None` to retain the previous behavior:
no request ID and an ephemeral receiving identity for Nostr transport.

Existing serialized FFI parameter records may omit the new fields. Generated
binding constructors default them to `None`/`nil`/`null`.

### Spending-condition validation

Request creation now reports errors instead of skipping malformed spending
keys or capping an oversized signature threshold. An explicitly empty key
list and simultaneous `hash` and `preimage` inputs also return errors.

Pass `pubkeys = None` when no signing keys are intended. When providing keys,
use a signature threshold from one through the number of keys, and supply at
most one of `hash` or `preimage`. These checks apply to Rust, CLI, and FFI
callers.
